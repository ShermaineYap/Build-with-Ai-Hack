Baca Dulu app map

A take-home guide to how the proof of concept works and where to change things. It's a snapshot of the code at the commit noted at the bottom, so details can drift as the code changes.

What it is

One web page and one server function. You paste a Malaysian offer letter. The server finds the salary and risky clauses (with built-in rules, or Gemini if a key is set), works out take-home pay with fixed arithmetic, writes questions for HR, and sends everything back. The page draws the payslip, the flag cards and the questions, and highlights each quoted sentence in your letter.

One action, end to end: Decode letter

Reference route through the code

This route wasn't walked through interactively; it's here for when you want to explore.

  1. The button. app/page.tsx, function decode. It checks the letter is at least 200 characters, POSTs it to /api/decode, and stores the DecodeResult in state. Everything on screen after that is drawn from that one object.
  2. Reading the letter. lib/rules.ts, function detectClauses. It runs one small detector per clause type (search for function bond(, function notice(…). Each one finds sentences with splitSentences from lib/text.ts, which keeps the exact character positions. That's why a card can highlight its sentence.
  3. The money. lib/statutory.ts, function computeTakeHome. Plain arithmetic for EPF, SOCSO, EIS and PCB. tests/statutory.test.ts checks it against hand-worked values for the sample letter (RM3,800 gross → RM3,415.94).

To change this, start here

  • Wording on a flag card → the detector in lib/rules.ts (the last two strings passed to clause(...)).
  • A new kind of clause → add a type in lib/types.ts, a detector in lib/rules.ts, a question in lib/questions.ts, and a test in tests/rules.test.ts.
  • Tax bands or contribution rates → constants at the top of lib/statutory.ts; run npm test afterwards.
  • Colours, fonts, the payslip look → CSS variables at the top of app/globals.css.
  • The demo letter → lib/sample-letter.ts.

A practice to reuse

Write "done" as something you can check, then make a test say it. The scope defined done as "the app catches the bond, probation, notice and allowance traps in the sample letter". tests/rules.test.ts turns each of those into an assertion, and the acceptance criterion "every quote is verbatim" became expect(SAMPLE_LETTER.slice(c.start, c.end)).toBe(c.quote). The same check later protected the AI reader: tests/ai.test.ts proves an invented quote is dropped. On your next project, turn each line of your "what working looks like" section into a test before polishing the UI.

Run it again

npm install, then npm run dev, then open http://localhost:3000. npm test runs the 43 tests. For Gemini, copy .env.example to .env.local and add a key.
